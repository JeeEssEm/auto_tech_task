# Unit Economics: стоимость 1 запроса в Auto-TZ

## 1. Что считаем

Ниже расчет переменной стоимости LLM на 1 пользовательский запрос для текущего pipeline v3.

В проекте участвуют разные модели по ролям:

- Intent Router: `openai/gpt-oss-120b`
- Harvester: `deepseek/deepseek-chat`
- Grouping Judge: `anthropic/claude-3.5-haiku`
- Consultant: `qwen/qwen3-235b-a22b-2507`
- Architect: `qwen/qwen3.5-plus-02-15`

## 2. Принятые тарифы (OpenRouter, ориентир)

Тарифы взяты как ориентировочные по публичным карточкам моделей (USD за 1M токенов):

- `openai/gpt-oss-120b`: input 0.039, output 0.190
- `deepseek/deepseek-chat`: input 0.320, output 0.890
- `anthropic/claude-3.5-haiku`: input 0.800, output 4.000
- `qwen/qwen3-235b-a22b-2507`: input 0.071, output 0.100
- `qwen/qwen3.5-plus-02-15`: input 0.260, output 1.560

Примечание по `qwen3.5-plus-02-15`: у провайдера есть ценовые диапазоны по контексту; в расчете используется нижний tier (типовой для контекста <= 256K).

## 3. Формула

Стоимость шага:

$$
C_{step} = \frac{T_{in}}{10^6} \cdot P_{in} + \frac{T_{out}}{10^6} \cdot P_{out}
$$

Где:

- $T_{in}$ - входные токены шага
- $T_{out}$ - выходные токены шага
- $P_{in}, P_{out}$ - цены модели за 1M токенов

Итог по запросу:

$$
C_{request} = \sum C_{step}
$$

## 4. Профиль A: первичная генерация ТЗ

Сценарий: пользователь запускает `POST /tz/{chat_id}/generate`, есть 2 файла после парсинга, обновляется несколько секций.

### 4.1 Допущения по токенам

- Intent Router: 3,000 in / 180 out
- Harvester: 17,600 in / 1,200 out
- Grouping Judge: 6,300 in / 2,700 out
- Architect (plan + section writes): 20,500 in / 3,900 out
- Consultant: 0 (не вызывается в этом сценарии)

### 4.2 Стоимость по шагам

- Intent Router: $0.000151
- Harvester: $0.006700
- Grouping Judge: $0.015840
- Architect: $0.011414

### 4.3 Итого

$$
C_{generate} \approx 0.0341\ \text{USD}
$$

Оценка: около **$0.03-$0.04** за 1 генерацию при указанном профиле нагрузки.

## 5. Профиль B: вопрос по текущему проекту (consultant-only)

Сценарий: пользователь задает вопрос по уже собранному проекту без массивной перегенерации документа.

### 5.1 Допущения по токенам

- Intent Router: 2,000 in / 100 out
- Consultant: 8,000 in / 1,200 out
- Остальные behavior-ветки: 0

### 5.2 Итого

- Intent Router: ~$0.000097
- Consultant: ~$0.000688

$$
C_{consult} \approx 0.000785\ \text{USD}
$$

Оценка: меньше **$0.001** за 1 консультативный запрос.

## 6. Диапазон чувствительности

Фактическая цена сильно зависит от:

- числа и объема attachment-источников;
- числа конфликтов (рост вызовов Grouping Judge);
- количества секций, затронутых Architect;
- выбранного провайдера и динамического routing в OpenRouter;
- доли повторных перегенераций блока.

Практически полезно закладывать:

- lightweight запрос: $0.001-$0.010
- типовая генерация: $0.020-$0.070
- тяжелая генерация (много конфликтов/секций): $0.070+

## 7. Локальный режим (Ollama)

Если behavior-модели переводятся на `provider=local` (Ollama), прямой API cost может стремиться к нулю, но появляется инфраструктурная стоимость:

- GPU/CPU время
- электроэнергия
- амортизация железа
- DevOps сопровождение

Для on-prem оценки рекомендуется считать cost per GPU-hour и переводить его в стоимость 1 запроса по среднему latency/token throughput.

## 8. Как сделать расчет точным в проде

Чтобы перейти от оценки к точному PnL:

1. Логировать usage per model (input/output tokens) в каждом behavior.
2. Ежедневно подтягивать актуальный price list провайдеров.
3. Считать rolling среднюю стоимость на запрос и p95.
4. Разделить метрики по сценариям: generate, update, regenerate block, consultant Q&A.
5. Добавить алерты при отклонении unit-cost выше планового порога.
